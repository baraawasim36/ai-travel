The coding agent report is the authoritative baseline for the current repository state. It found the app to be a Flutter prototype/active-development codebase with several launch blockers, and it did not modify source code.

## Critical baseline findings to verify and execute
- Supabase is the current backend baseline; Firebase migration is not part of MVP.
- Supabase configuration currently requires valid runtime configuration; masked/invalid credentials must not be hard-coded.
- Google Maps/Directions and Gemini credentials must be externalized and rotated/restricted as appropriate.
- The current code references many backend tables and storage objects without repository migrations; the target must introduce versioned SQL migrations and RLS policies.
- Guide/destination catalog content contains static/demo data and must be migrated to backend data.
- Payment is currently a receipt/manual-review pattern, not a verified gateway transaction; MVP must explicitly model manual verification rather than pretending it is a live gateway.
- Duplicate guide booking controller implementations must be consolidated.
- Placeholder routes/screens/assets and example.com content are P0/P1 cleanup items.
- No Flutter tests were found and local Flutter tooling was unavailable during the reported audit; the agent must document the actual local result rather than assume availability.
